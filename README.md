# llmproxy

Прозрачный TCP-шлюз для сайтов ChatGPT, OpenAI и Claude и регистрация клиентских IP по секретной ссылке.

Шлюз не расшифровывает TLS. Он читает имя из ClientHello (SNI), проверяет, что имя в списке, резолвит его обычным DNS и прокидывает исходные байты на настоящий сервер. Клиентский сертификат и содержимое запросов не видны.

Пускать трафик можно только с адресов из постоянного списка сетей или с IP, который открыл секретную ссылку.

## Как это устроено

На клиентах DNS имён `chatgpt.com`, `openai.com`, `anthropic.com`, `claude.ai` и их поддоменов указывает на эту машину. На самой машине DNS остаётся настоящим: иначе шлюз зациклится на себя.

```
клиент  --DNS-->  адрес шлюза
клиент  --TCP 443, TLS-->  шлюз  --SNI-->  настоящий chatgpt / claude
клиент  --HTTP :61150/<секрет>-->  свой IP попадает в список
```

В одном процессе два слушателя:

| Порт | Назначение |
| --- | --- |
| `443` | TCP-прокидка TLS |
| `61150` | Страница регистрации IP |

Чужой SNI не превращает шлюз в открытый прокси: имя должно совпасть с шаблоном из `proxy.hosts`. Адрес назначения должен быть глобальным; частные, мультикаст и неспецифицированные адреса отбрасываются. Локальные адреса самой машины добавляются в запрет автоматически, чтобы резолв не упёрся обратно в шлюз.

## Требования

Python 3.11 или новее. Сторонних пакетов нет.

Порт 443 на хосте обычно требует root или capability `CAP_NET_BIND_SERVICE`.

## Запуск

```bash
python3 -m llmproxy init --config config.toml
python3 -m llmproxy serve --config config.toml
```

`init` создаёт `config.toml` со случайным секретом и печатает ссылку вида `http://<адрес>:61150/<секрет>`. Существующий файл не перезаписывается.

`config.toml` и каталог `data/` в git не попадают: в репозитории лежит только `config.example.toml`.

## Docker

```bash
docker compose up -d --build
```

Контейнер работает в сети хоста (`network_mode: host`), поэтому порты из конфига слушаются прямо на машине. `config.toml` монтируется только для чтения, `data/` — список зарегистрированных IP.

Перед первым запуском нужен свой `config.toml` (команда `init` выше). Образ сам конфиг не создаёт.

## Регистрация клиента

1. С клиента открыть `http://<адрес-шлюза>:61150/<секрет>`.
2. На этом клиенте направить DNS разрешённых имён на адрес шлюза: файл hosts, split-DNS или роутер.

Страница отвечает по-русски:

- **Готово** — IP добавлен до даты.
- **Уже в списке** — запись ещё действует, срок не сдвигается; либо адрес входит в постоянную сеть.
- **404** — секрет не совпал. Тело ответа: «Не найдено».

Повторный заход до истечения срока дату не продлевает. Просроченная запись обновляется: новая дата считается от сегодняшнего дня плюс `ttl_days`. Адрес из `allowlist.permanent` дату не получает.

Секрет сравнивается по SHA-256 через `hmac.compare_digest`. В конфиге он обязан быть своим и не короче 16 символов; значения `change-me` и `replace-me` не принимаются.

## Конфигурация

```toml
[listen]
enroll_host = "0.0.0.0"
enroll_port = 61150
proxy_host = "0.0.0.0"
proxy_port = 443

[enroll]
secret = "<не короче 16 символов>"
ttl_days = 30

[allowlist]
path = "data/allowlist.json"
permanent = ["203.0.113.10/32"]

[proxy]
upstream_port = 443
hello_timeout = 5
connect_timeout = 10
deny_ips = []
allow_private_upstreams = false
hosts = [
  "chatgpt.com",
  "*.chatgpt.com",
]
```

| Поле | Смысл |
| --- | --- |
| `listen.*` | Адреса и порты регистрации и шлюза |
| `enroll.secret` | Секрет в пути ссылки |
| `enroll.ttl_days` | Срок новой регистрации, не меньше 1 |
| `allowlist.path` | JSON со сроками. Относительный путь считается от каталога конфига |
| `allowlist.permanent` | Сети CIDR, которым ссылка не нужна. Префикс обязателен в каноническом виде |
| `proxy.hosts` | Точные имена и шаблоны `*.домен`. `*.openai.com` покрывает поддомены и не покрывает сам `openai.com` |
| `proxy.deny_ips` | Адреса назначения, на которые шлюз не пойдёт. Сюда же имеет смысл вписать публичный адрес самого прокси |
| `proxy.allow_private_upstreams` | Разрешить частные адреса назначения. По умолчанию выключено |
| `proxy.hello_timeout` | Сколько секунд ждать ClientHello |
| `proxy.connect_timeout` | Сколько секунд ждать соединение с одним адресом назначения |
| `proxy.upstream_port` | Порт настоящего сервера, по умолчанию 443 |

Если `proxy.hosts` не задан, берётся встроенный список: `chatgpt.com`, `openai.com`, `oaistatic.com`, `oaiusercontent.com`, `anthropic.com`, `claude.ai`, `claude.com` и шаблоны `*.` для каждого из них.

## Список доступа

`data/allowlist.json` — словарь «IP → дата окончания» в формате `YYYY-MM-DD`:

```json
{
  "203.0.113.10": "2026-11-10"
}
```

Запись атомарная (временный файл и `os.replace`), файл создаётся с правами `0600`. Просроченные ключи из файла сами не удаляются: при проверке они просто не считаются активными, а следующий заход по ссылке перезаписывает дату.

Постоянные сети живут только в конфиге и в этот файл не пишутся.

## Что соединение закрывается без прокидки

- IP нет ни в постоянном списке, ни в действующей записи.
- Клиент не прислал целый ClientHello за `hello_timeout`.
- В ClientHello нет SNI, либо имя не совпало ни с одним шаблоном.
- Имя не резолвится, все адреса запрещены, либо ни к одному не удалось подключиться.

В журнал пишется причина на уровне INFO. Содержимое TLS в журнал не попадает.
